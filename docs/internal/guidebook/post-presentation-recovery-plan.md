# Post-presentation recovery plan

## First recovery tranche

1. backtester/runtime reliability
2. data quality and historical coverage
3. UI responsiveness and navigation polish
4. admin/data command usefulness
5. auth/provider transitional debt

## Second recovery tranche

1. canonical strategy definitions and versions
2. saved parameter sets and runs
3. promotion from backtest to live monitoring
4. worker-backed strategy deployment nodes

## Third recovery tranche

1. ML strategy lab
2. TradingView/webhook bridge
3. deeper analytics and external integrations

## Recovery rule

Do not resume broad feature addition until the current trust boundaries, data quality, and strategy model are strong enough to support them.
