# How to use this documentation

Mahita now has enough moving pieces that a reviewer can get lost if they open random pages. This guide provides the fastest reading order.

## If you only have 20 minutes

Read these five pages in order:

1. `Executive Overview`
2. `Two-Quarter Research Timeline`
3. `Senior Project Report Draft`
4. `Presentation Outline`
5. `Current State And Limitations`

That sequence tells the story, shows the engineering intent, and makes the unfinished work explicit.

## If you are a faculty reviewer

Use this path:

1. Read the executive overview to understand the project goal.
2. Read the timeline to understand why the scope changed between quarters.
3. Read the report draft for the formal engineering narrative.
4. Read the presentation materials to see how the demo is structured.
5. Read the current-state and limitations page to understand what is complete, transitional, and deferred.
6. Read `Platform Data Summary` if you want a concise explanation of how the market-data system currently works.

## If you are a developer or future maintainer

After the public overview, sign in and continue with:

1. `Architecture Guidebook`
2. `Authentication Guidebook`
3. `Data / Provider / Brokerage Model`
4. `Platform Data Architecture Audit`
5. `Testing Guidebook`
6. `Documentation Maintenance Workflow`

## Status badge meanings

- `Current`: this page reflects the current intended truth.
- `Transitional`: this page is accurate, but describes architecture that is still in an intermediate state.
- `Historical`: preserved for context; do not treat it as the latest truth by default.
- `Future Work`: design direction, not implemented capability.

## Truthfulness rule

Mahita should not be presented as a finished trading platform. The correct framing is:

- a working foundation for a brokerage-connected trading terminal
- a prototype backtesting and strategy research environment
- a project with clear future directions in data quality, strategy deployment, and ML-assisted research
