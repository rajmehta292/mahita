# Advisor conversation guide

## Core framing

Do not frame the project as “I ran out of time and didn’t finish.”

Frame it as:

“I established the correct system foundation, proved the core user and brokerage flows, and identified the exact architectural work required for the next phase.”

## What to emphasize

- the project scope is inherently large for an undergraduate capstone
- the platform now has real auth, user state, Schwab integration, and operator boundaries
- the key remaining work is refinement, hardening, and unification of the strategy path

## What to say about unfinished work

Use this pattern:

1. state what is incomplete,
2. explain why it is incomplete,
3. explain what architectural task fixes it,
4. show that the work is documented.

Example:

“Backtesting is still a prototype. The limitation is not just UI polish; it is that the strategy and deployment models are not yet unified. I documented that as a concrete next architecture tranche.”

## What not to do

- do not claim the product is production-ready
- do not hide bugs or scope changes
- do not oversell the ML work as finished implementation

## Closing line

“Even where Mahita is unfinished, I can explain exactly why it is unfinished, how the system is structured today, and what the next correct engineering steps are.”
